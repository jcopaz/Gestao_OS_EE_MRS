2. O Ecossistema (Arquitetura do Projeto)
Frontend / Painel: Streamlit (com customizações em HTML/CSS/JS e ECharts).
Motor Antifraude / API: FastAPI hospedado no Render. Endpoints: /sincronizar_baixa_offline, /health, /publicar_pacote, /pacote/{id}.
Banco de Dados: Neon Serverless (PostgreSQL). Tabelas: baixas, evidencias, usuarios, pwa_pacotes.
Storage de Fotos: Supabase.
Modo Offline (PWA): Arquivo HTML/JS gerado dinamicamente que usa IndexedDB para armazenar apontamentos em lote e fotos na ausência de internet, sincronizando via API (FormData) quando a conexão volta. DISTRIBUÍDO COMO PWA EM HTTPS (nunca file://): publicar rota (/publicar_pacote) e abrir /pacote/{id} 1x online no celular antes de usar offline.

3. A Espinha Dorsal (Regras de Código Inegociáveis)
Estrutura de Sessões: O código do app.py é estritamente organizado em blocos modulares (#region SESSÃO X e #region X.Y). O #endregion deve ser SEMPRE a última linha do bloco, nunca colado a outros comandos.
Limpeza e Indentação: Use sempre 4 espaços. Jamais misture TABs. Não permita HTML escapado (&lt;, &gt;, &amp;) no código final gerado.
Unicidade Estrutural: Só deve existir um único with tab1: e with tab2: por caminho de execução. As telas Governança e Admin rodam em coluna 0 e usam blocos 10.3.x guardados por "if tab2 is not None:". Por isso, tab1 e tab2 DEVEM ser inicializados como None ANTES do roteamento (Sessão 10.1) para evitar NameError.
Ciclo de Vida (State): O Streamlit é efêmero. Qualquer dado que precise persistir (filtros, GPS, ações, login) deve ser salvo no st.session_state e, se necessário, disparar st.rerun(). O login também é persistido via token HMAC na URL (?sid=, TTL 12h, segredo AUTH_TOKEN_SECRET) para sobreviver à câmera no mobile.
Cache: @st.cache_data só invalida se a chave/hash mudar. Hashes de overlay (ex.: _hash_baixas) DEVEM incluir MAX(realizado_em) para captar UPDATEs feitos via ON CONFLICT.
Merges de overlay 1:N (evidencias) exigem drop_duplicates(subset=["os_ref_match"]) ANTES do merge, senão duplicam linhas na exibição das baixas.

4. Fluxo de Dados e Performance (A Fonte da Verdade)
Camadas Lineares: Base Bruta SAP -> Overlay PostgreSQL (Baixas) -> df_visao (Colunas auxiliares limpas com Regex) -> Sidebar (Filtros) -> df_filtrado (Fonte única de toda a visualização na tela).
Isolamento de Banco: As tabelas de operação (baixas, evidencias) e segurança (usuarios) são independentes. Não acople segurança à lógica operacional. baixas usa ON CONFLICT(os) e evidencias ON CONFLICT(ativo,atividade) — upsert idempotente (o banco não duplica).
Geolocalização (Mapas e API): O GPS online usa streamlit_js_eval (polling). Mapas Folium usam max_bounds=True com foco em SP. A malha ferroviária (KML) DEVE ser lida e simplificada (geopandas.simplify) através de uma função com @st.cache_data. Nunca leia o KML do disco a cada interação.
Upload de Evidências: Nunca renderize imagens Base64 nativas no st.dataframe. Use st.column_config.LinkColumn apontando para o Supabase. Toda imagem enviada ao Supabase deve passar pelo Pillow (PIL): aplicar ImageOps.exif_transpose (corrige orientação), .convert('RGB') e comprimir (quality=75, optimize=True).
Filtros Inteligentes: Múltiplos filtros na sidebar devem ser envelopados em um st.form com um botão "Aplicar Filtros" (evita re-runs). Se o st.session_state["perfil"] == "Técnico", a sessão de filtros deve ser totalmente ocultada (retornar silenciosamente).
Roteirização: Raio inicial de 1 km (era 10 km). Raio e filtro por ativo NÃO recalculam automaticamente — aplicação via botão "Filtrar" (st.session_state["raio_aplicado"]/["ativo_aplicado"]). df_recomendado inicia como pd.DataFrame() vazio; antes de acessar colunas, checar df.empty E "coluna" in df.columns (atenção com raio de 1 km = "zero OS").

5. Lógicas de Negócio Críticas
Sanitização SAP: Dados extraídos do SAP possuem espaços fantasmas. Ao cruzar Coordenação ou Pátio, use regex: re.sub(r'\s+', ' ', val).strip().upper().
Integração SAP (Apontamento de Tempo): O SAP recusa início maior que fim no mesmo dia. Se o técnico preencher um turno que cruza a meia noite (ex: 22h às 03h), a API/Streamlit deve retroagir a "Data de Início" para D-1. A duração limite teórica é de 14h. No modo Offline, durações calculadas acima de 12h exigem um confirm() do usuário antes de salvar na memória.
Baixa em massa (online e offline): há um modo "Horário único" (toggle, default ligado) — um só conjunto Data/Hora Início e Fim replicado para TODAS as OS selecionadas. O modo individual continua disponível.
Regra de Turnos: O sistema classifica operações ativamente:
- Turno Noite: 19h-07h (Todos os dias).
- Administrativo: 08h-17h30 (Segunda a Sexta).
- Turno Dia: 07h-19h (Finais de semana) + Janelas de Seg-Sex (07h-07h59 e 17h31-18h59).
Trava de Priorização Operacional (Locking): QUALQUER OS "Muito Alta" pendente trava as de menor criticidade do MESMO grupo (Ativo × Tipo de Intervalo), INDEPENDENTE da data de programação (mask_critica = Criticidade_rank == 1, sem condição de data). CI (Com Intervalo) e SI (Sem Intervalo) são filas independentes. O Backlog é priorizado apenas na ordenação (Ordem_Prazo), não no bloqueio. As OS bloqueadas ficam VISÍVEIS (acinzentadas + cadeado 🔒): no online, em um expander "🔒 OS bloqueadas (N)" fora do multiselect; no offline, com card travado e cadeado no título.
Motor Antifraude (Geofencing): Validação estrita: distância máxima de 2.0 km do ativo (haversine_vectorized). Se o backend Neon dormir (Cold Start), a API tenta 3x. Bypass secreto na API e HTML para testes: token mrs2026.
GPS OBRIGATÓRIO (regra vigente pós 03/Jul): tanto no online quanto no offline, sem localização do NAVEGADOR o app NÃO grava. A leitura de EXIF da foto foi REMOVIDA (era redundância e mascarava GPS ausente, causando o falso "5655 km"). A foto offline é SEMPRE comprimida. A API rejeita com HTTP 400 quando lat/lon == 0,0. NÃO reintroduzir fallback de EXIF.

9. Matriz de Colaboração e Diagnóstico IA (O "Guia de Sobrevivência")
Diagnóstico "Estrutura Antes da Lógica": Cerca de 80% dos travamentos fatais, erros de indentação ou telas brancas nascem de desorganização estrutural. Antes de investigar DataFrames ou regras de negócio, valide o esqueleto: um único "with tab1:"/"with tab2:" por caminho, tab1/tab2 inicializados como None antes do roteamento, nenhum "#endregion" desalinhado, e nenhum símbolo HTML escapado (&lt;, &gt;).
Ciclo de Vida e persistência (Ghost State): O Streamlit reexecuta todo o script a cada clique. Se um filtro sumir, uma ação não persistir ou uma OS já baixada continuar "disponível", a causa raiz costuma ser gestão de estado OU cache não invalidado (hash sem MAX(realizado_em)). Grave interações persistentes no st.session_state e use st.rerun().
Duplicação de registros: se uma OS aparece 2x nas baixas, é merge 1:N de evidencias sem drop_duplicates — não é duplicação no banco (upsert idempotente).
Manipulação de F-Strings no Modo Offline: As Sessões 3.9 a 3.13 geram o HTML offline injetando JavaScript dentro de f-strings triplas do Python. Qualquer ajuste no front-end offline exige que TODAS as chaves estruturais do JavaScript sejam escritas de forma duplicada {{ }} para evitar conflito com o interpretador de strings do Python.
Offline / PWA: file:// não tem contexto seguro (geolocation bloqueada). O offline só funciona distribuído como PWA HTTPS (publicar rota → abrir /pacote/{id} 1x online). A OS deve sumir da lista após gravar/sincronizar (osGravadasSet atualizado no boot, após gravar e após sync).
Abordagem Evolutiva Incremental: Priorize a fundação transacional (banco local, sincronização, contratos de API) e garanta o fluxo de dados robusto ANTES do refinamento estético/CSS.
